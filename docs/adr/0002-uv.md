# ADR-0002: uv for environment and dependency management

- **Status:** Proposed
- **Date:** 2026-11-17

## Context

The project needs an isolated Python environment and reproducible dependencies.

## Verified Facts

- `uv.lock` exists and is versioned (commit `0ca1e45`).
- uv 0.13.9 is installed in the development environment; `.venv/pyvenv.cfg` records `uv = 0.13.9`.
- `.venv` contains a `.gitignore` generated by uv that excludes the whole directory from Git.
- `pyproject.toml` has no `[build-system]` table. `uv.lock` records the project as `source = { virtual = "." }`: uv manages the environment and dependencies, but does not install CompAI itself as a package.
- Rebuilding the development environment from `pyproject.toml` and `uv.lock` with `uv sync` was verified in practice by the project owner (2026-11-17, uv 0.13.9).

## Decision

Use uv to create the project environment, resolve dependencies, and maintain `uv.lock`.

## Known Reasons

- uv was proposed in the original roadmap and adopted as a pragmatic initial choice.
- No formal comparison with alternatives was performed.

## Hypotheses

- uv will cover the environment and dependency needs of P0. Not verified.
- uv will remain adequate as CompAI evolves beyond P0. Not verified.

## Open Questions

- Alternatives not evaluated: pip + venv, Poetry, PDM, Hatch.
- Policy for pinning or updating the uv version.
- Packaging CompAI (`[build-system]`, project layout): to be studied when `src/` is designed.

## Consequences

- `pyproject.toml` and `uv.lock` are versioned; `.venv` is not.
- Contributors need uv installed.
- A fresh development environment can be reconstructed using the committed project configuration and lockfile.
- CompAI is not currently configured for package building or distribution.
