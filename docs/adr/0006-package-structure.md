# ADR-0006: Installable package with `src/` layout and `uv_build`

- **Status:** Accepted
- **Date:** 2026-11-22

## Context

Phase 1 starts with package structure ([roadmap](../roadmap.md), Phase 1). CompAI has no Python package yet, and `pyproject.toml` has no `[build-system]` table, so uv treats the project as virtual: it installs the dependencies but not CompAI itself. Tests in `tests/` cannot import CompAI ([ADR-0005](0005-quality-tools.md), Open Questions).

## Verified Facts

- `pyproject.toml` has no `[build-system]` table, and `.venv\Lib\site-packages` contains no `compai` entry and no `.pth` file (checked on 2026-11-22).
- Installed uv version: 0.13.9 (`uv --version`).
- In a probe project outside the repository, `uv init --package` (uv 0.13.9) generated the `src/<package>/__init__.py` layout and this table:

  ```toml
  [build-system]
  requires = ["uv_build>=0.13.9,<0.14.0"]
  build-backend = "uv_build"
  ```

- Before adding `[build-system]`, with `src/compai/__init__.py` in place:
  - `uv run pytest` reported `2 failed, 1 passed`: `ModuleNotFoundError: No module named 'compai'` and `PackageNotFoundError: No package metadata was found for compai`.
  - `sys.path` contained the current directory (`''`), the standard library, and `.venv\Lib\site-packages`, but no `src` path. `import compai` from the repository root failed; from inside `src/` it succeeded.
- After adding `[build-system]` and running `uv sync` (verified by the project owner and checked on 2026-11-22):
  - `site-packages` contains `compai.pth`, whose only line is `C:\Proyectos\CompAI\src`, and `compai-0.1.0.dist-info\`.
  - `sys.path` includes `C:\Proyectos\CompAI\src`, and `compai.__file__` points to `src\compai\__init__.py`.
  - A change to the module docstring was visible without reinstalling (editable install).
  - In `uv.lock`, CompAI changed from `source = { virtual = "." }` to `source = { editable = "." }`. `uv lock --check` exits with 0.
  - `uv run pytest` reports `3 passed`, including `version("compai") == "0.1.0"`.

## Decision

- CompAI is an **installable package**: `pyproject.toml` declares a `[build-system]`, and `uv sync` installs CompAI into `.venv` in editable mode.
- **`src/` layout:** the package lives in `src/compai/`.
- **Build backend:** `uv_build`, with the version range generated by uv (`>=0.13.9,<0.14.0`).
- `src/compai/__init__.py` contains only a module docstring. The version is declared only in `pyproject.toml`; code that needs it reads it with `importlib.metadata.version("compai")`.
- No `[project.scripts]` entry point until Phase 2 (CLI Foundation).

## Known Reasons

Discussed with the project owner on 2026-11-22:

- The P0 outcome is a CLI run from the terminal ([roadmap](../roadmap.md) §2). A terminal command requires an installable package with an entry point; a virtual project cannot provide it.
- With the `src/` layout, the package cannot be imported by accident from the repository root. Tests only pass if CompAI is actually installed, so a broken installation makes them fail.
- A virtual project with the `src/` layout would need `pythonpath = ["src"]` in pytest, and the import would only work inside pytest.
- `uv_build` is the backend generated by `uv init --package`, it is maintained by the same project as uv, and it expects the `src/` layout by default.
- Declaring the version only in `pyproject.toml` avoids two copies of the same value getting out of sync.
- The entry point is postponed because it requires a CLI module, which belongs to Phase 2. Creating it now would anticipate design decisions (CLI framework, commands, separation between CLI and logic) that Phase 1 prepares.

## Hypotheses

- The `src/` layout and `uv_build` remain adequate as the package grows into several subpackages. Not verified.

## Open Questions

- Alternatives not evaluated in practice: `hatchling`, `setuptools`, flat layout, virtual project with `pythonpath`.

## Consequences

- `uv sync` builds and installs CompAI; `uv.lock` records CompAI as an editable package.
- The `uv_build` upper bound (`<0.14.0`) must be raised manually when uv is upgraded to a version outside the range.
- `import compai` works anywhere in the environment (tests, Python console, scripts), not only inside pytest.
- Adding the CLI command in Phase 2 requires only a `[project.scripts]` entry and the CLI module.
